# Codex Desktop MVP 구현 계획

사용자가 기존 입력창에서 프로젝트별 컨트롤러에 작업을 위임하는 흐름을 구현합니다.
현재 대화의 프로젝트는 `tttaliesin`이며 새 저장소는 그 프로젝트 아래의 Git 저장소입니다.
대화 도구의 프로젝트와 작업 저장소 루트를 각각 기록합니다.

## 구현 범위

- [x] 새 로컬 Git 저장소 생성.
- [x] 실제 대화 생성·대기·읽기·보관·복원 도구 확인.
- [x] 프로젝트·작업·실행의 상태 코어와 SQLite 저장소.
- [x] Codex 도구 계획·반환값 어댑터와 JSON CLI.
- [x] 컨트롤러·워커 스킬과 독립 설치 패키지.
- [x] 대기·검증·중복·응답 유실·오래된 결과의 단위 검증.
- [x] 이동 설치 패키지로 실제 워커 생성·재사용·검증 후 보관·후속 복원.

## 관찰과 수용 기준

현재 프로젝트의 대화 도구 정의는 모델·추론 강도 지정과 보관·복원을 제공합니다.
초기 검증 워커의 실제 결과와 보관·복원 응답을 확인했습니다.
이 관찰은 다른 설치 환경의 기능 가용성을 보장하지 않습니다.

설치 패키지의 CLI가 계획한 실제 앱 호출을 컨트롤러가 실행해야 수용합니다.
동일 작업의 후속 요청이 같은 worker threadId를 유지해야 합니다.
새 runId에는 검증 상태가 초기화돼야 합니다.
검증 미확인·실패 또는 승인·답변 대기가 있으면 보관을 거부해야 합니다.
실제 워커가 생성한 실행별 marker를 컨트롤러가 독립적으로 확인해야 합니다.
보관 응답과 복원 응답을 기록한 뒤에만 로컬 보관 상태를 변경해야 합니다.
동일 requestId의 재전송은 대화나 실행을 추가 생성하지 않아야 합니다.

## 기술 선택

Node.js 24 ESM과 기본 제공 `node:sqlite`를 사용합니다.
실행 의존성은 추가하지 않습니다.
공통 코어는 호스트 대화 도구를 직접 호출하지 않습니다.
설치 패키지를 구성한 뒤 소스 체크아웃을 참조하지 않는 위치로 복사해 검증합니다.
OpenSpec CLI 조회에서 저장소 루트가 없는 것을 확인했습니다.
이번 요청은 OpenSpec 도입을 포함하지 않아 이 계획을 저장소 문서로 유지합니다.
